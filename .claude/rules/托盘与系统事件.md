# 托盘、系统事件、开机自启的坑

- 托盘的 `set_icon` / `set_menu` 等在非主线程调用时会阻塞等待主线程；调用时如果还拿着锁，就可能死锁。托盘更新一律用 `run_on_main_thread` 投递，投递前放开所有锁。
- Windows 不允许"没有可见窗口"的程序阻止关机：5 秒内不回复 `WM_QUERYENDSESSION` 就会被结束。开机自启从没弹窗口、或窗口关到托盘时，`sysevents.rs` 的事件窗口必须是 `WS_VISIBLE`（0×0、`WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`），不要改回 message-only 或不可见窗口。message-only 窗口也收不到电源广播和关机消息。
- `tauri-plugin-single-instance` 只按 identifier 判断是不是同一个程序，调试版和安装版会互相认成同一个，所以只在发布版启用；否则装了安装版并常驻托盘时，`npm run tauri dev` 一启动就退出。
- `tauri-plugin-autostart` 默认用 productName 作为注册表 Run 项的名字，调试版的项要用单独的名字，免得手动开开关时覆盖安装版的开机自启。开发时不要在自己电脑上注册调试版的开机自启。
- 合盖时常常先锁屏再睡眠：离开同步由"锁屏"那一轮开始，唤醒后的到达同步要等任何离开类的那一轮结束，不能只等"睡眠"那一轮。
