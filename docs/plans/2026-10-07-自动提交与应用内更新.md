# 自动提交与应用内更新

- 状态：进行中
- 日期：2026-10-07
- 需求原话：
  1. 在添加项目页，添加搜索功能，扫描出来的内容过多不好找
  2. 更新功能，github 发布新版本可拉取更新
  3. 有时候我在工作区中有些内容是没提交的，我想做的是，我自动同步状态，软件会按照固定格式创建一个 git commit，然后将文件推送到 github。类似于 obsidian 上的 git 插件，只不过我这个会管理很多项目

### 组 B：一键同步时自动提交并推送（按项目开关）

- 背景：Git SyncDeck 管理多个本地 Git 项目。现在点"一键同步"时，"有未提交改动"（dirty）的项目只会记为异常、不处理。用户想要类似 Obsidian Git 插件的效果：**对打开了"自动提交"的项目**，一键同步时自动按固定格式提交所有改动并推送。已确认：只在一键同步时触发（不做后台定时）；每个项目单独开关，默认关；提交信息模板默认 `自动同步：{date} 来自 {host}`，设置里可改。安全红线不变：不强推、不 rebase、不 stash、不 reset、不自动合并；所有 git 子进程只能从 `git.rs` 的 `run_git` 创建，受白名单约束。
- 要做：
  1. 配置与模型：`config.rs` 的 `StoredProject` 加 `auto_commit: bool`（`#[serde(default)]`，旧配置读出来为 false），`StoredSettings` 加 `commit_template: Option<String>`；`model.rs` 的 `Project` 加 `auto_commit`（前端 `autoCommit`），`Settings` / `SettingsPatch` 加 `commit_template`（前端 `commitTemplate`，读取时空值回落为默认模板），`SyncOutcome` 加 `Committed`（前端 `"committed"`，含义"已自动提交并推送"）。前端 `src/types/index.ts` 同步改。（验证：`cargo test` 通过，旧 config.json 能正常读）
  2. 新命令 `set_auto_commit(project_id, enabled) -> Project`：写入配置并返回最新项目；在 `lib.rs` 的 `generate_handler!` 注册；`src/api/tauri.ts`、`src/mock/api.ts`、`src/api/index.ts` 加 `setAutoCommit(projectId: string, enabled: boolean): Promise<Project>`。（验证：`npm run build` 通过）
  3. 提交信息：模板占位符 `{date}` → 本地时间 `YYYY-MM-DD HH:mm`，`{host}` → 电脑名（Windows 取环境变量 `COMPUTERNAME`，取不到用"未知电脑"）。模板去掉空白后为空就用默认模板。写成纯函数并加单元测试。
  4. 一键同步逻辑（`ops.rs` 的 `sync_one` 及 `commands.rs` 的 `sync_all` 传参）：项目开了自动提交、状态是"有未提交改动"、有上游时：
     - 有冲突中的文件（未合并条目）或正在 merge → 不提交，记为异常，原因写清楚
     - 本地领先且落后（分叉）→ 不提交，记为异常
     - 落后于云端 → 先 `pull --ff-only --no-rebase --no-autostash`；git 拒绝（本地改动和云端改动碰到同一文件等）→ 不提交，记为异常，原因用 git 原文并说明"未提交任何内容"
     - 然后 `git add -A` → `git commit -m <信息>` → `push`（复用现有 `push`）；推送失败 → 提交保留在本地，记为异常，原因说明"已提交到本地，但推送失败：…"
     - 成功 → outcome `Committed`，`commits` = 推送的提交数，`lastSyncAt` 更新、遗留异常清除（和现有推送成功的处理一致）
     - 没开自动提交、或没有上游 → 保持现在的行为（记为异常）
     （验证：见第 6 项的集成测试）
  5. 界面：
     - 项目详情抽屉 `ProjectDetailSheet.tsx`：加"一键同步时自动提交"开关（用现有 `Checkbox` 或新增 shadcn `switch` 组件均可），旁边一行说明"一键同步时会把所有改动按固定格式提交并推送"；没有上游时开关可用但提示"没有上游分支，不会生效"
     - 项目列表 `ProjectList.tsx`：开了自动提交的项目在名称旁显示一个小标记（图标 + tooltip"自动提交"）
     - 状态说明 `src/lib/status.ts`：dirty 且开了自动提交时，"一键同步会怎么做"改成"自动提交并推送"；概览 `OverviewStats.tsx` 的"可自动同步"把这类项目算进去
     - 一键同步对话框 `SyncDialog.tsx`：`committed` 结果显示"已自动提交并推送 N 个提交"之类的文案
     - 设置页 `SettingsPage.tsx`：在"常规"和"外观"之间加"自动提交"一节：提交信息模板输入框（失焦或回车保存）、占位符说明、用当前时间和电脑名渲染的预览、"恢复默认"按钮。电脑名的预览可以在前端用占位文本，也可以加个命令取，二选一，取简单的
     - mock 实现（`src/mock/`）要支持开关和一键同步时的自动提交演示
     （验证：`npm run dev:mock` 在浏览器里走一遍：打开某 dirty 项目的开关 → 一键同步 → 该项目显示已自动提交并推送）
  6. 测试：在 `src-tauri/tests/` 里补集成测试（用 `scripts/make-test-repos.mjs` 生成的临时仓库，必要时扩展该脚本加新场景）：① 开自动提交的 dirty 仓库一键同步后，云端（本地裸仓库）最新提交的标题符合模板、工作区干净、状态已同步；② 没开开关的 dirty 仓库仍记为异常、没有新提交；③ dirty 且落后（改的不是同一文件）→ 先拉取再提交推送成功；④ dirty 且落后且改了同一文件 → 记为异常、没有新提交、本地改动还在。（验证：`cd src-tauri; cargo test` 全绿）
