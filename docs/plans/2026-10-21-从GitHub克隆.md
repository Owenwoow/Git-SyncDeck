# 从 GitHub 克隆项目

- 状态：已决定，未执行
- 日期：2026-10-21
- 需求原话：添加功能：我填入 github repo 地址，帮我遍历我仓库中的项目，供我同步选择，clone 到我默认指定的默认代码目录。
- 同批需求：设置页「后台运行」加关闭按钮、设置页排版、后台同步时显示进度。逐条问清后合并成一份交接单

```text
/dev-task
【目标】在「添加项目」页填一个 GitHub 账号，列出账号名下的仓库，勾选后克隆到默认代码目录并自动加入监控
【要做】
1. 「添加项目」页顶部分成「本地扫描」「从 GitHub 克隆」两个页签，「本地扫描」保持现状
2. 地址输入：账号主页（github.com/<用户名>）、用户名、单个仓库地址都接受，填单个仓库地址时只列那一个；记住上次填的（存 config.json）；第一次打开时默认填 gh 当前登录的账号
3. 列仓库：用 gh 命令行（gh repo list <账号> --json …）列出账号名下的仓库，包括私有、fork、已归档；fork 和已归档带标签、排在后面；按最近推送时间排序，可以搜索
4. 没装 gh 或 gh 没登录：改用 GitHub 公开接口（不带任何凭据）只列公开仓库，页面上提示"装好 gh 并运行 gh auth login 后能看到私有仓库"
5. 调用 gh 的子进程和 run_git 一样：不弹窗、有超时、走 SyncDeck 的代理设置（把代理传给 gh 的环境变量）；只允许只读命令（列仓库、读当前登录的账号），有白名单和单元测试
6. 标注：已经在本地的（默认代码目录或监控清单里有远程地址相同的仓库）标「已在本地」，不能勾；目标文件夹已被占用的标「文件夹已存在」，不能勾，不覆盖
7. 克隆：git 白名单加 clone，只允许 clone <地址> <目标路径> 加安全参数，禁止 --config / -c / --upload-pack / --template 等，补单元测试；克隆到 默认代码目录\仓库名，用 https 地址完整克隆；走代理；超时用「联网超时」设置；和刷新、一键同步共用 net_lock，不能同时进行
8. 进度：每个仓库一行，显示 等待 / 克隆中 / 完成 / 失败（附原因，原因里的地址去掉账号信息）；一个失败不影响其他
9. 克隆完自动加入监控，并联网检查一次
10. 克隆超时被强行终止后留下的半截文件夹：删掉，只删这次克隆新建的那个文件夹；CLAUDE.md 的"不删除任何文件"加上这条例外
11. 假数据实现（src/mock/api.ts）同步加上，演示模式能走完整个流程
12. 文档：README「页面与文件对照」、docs/requirements.md 新增一节、CLAUDE.md 里的白名单说明和例外
【不做】
- 读取 Git Credential Manager 里存的令牌，或者在设置里填令牌（选了 gh 方案）
- 列出组织的仓库、别人邀请协作的仓库
- 克隆进度百分比（如果第 3 条"后台同步进度"定了要显示百分比，再一起加）
- 浅克隆、用 SSH 地址克隆
- 克隆时弹出 GitHub 登录窗口（沿用 GIT_TERMINAL_PROMPT=0、GCM_INTERACTIVE=never）
- 改全局 git 配置，包括 gh auth setup-git
【已定的取舍】
- 私有仓库用 gh 命令行列出：SyncDeck 不碰令牌，守住"不读写凭据"；代价是每台电脑要装一次 gh 并登录
- 入口放在「添加项目」页的页签里：两者都是把项目加进来，侧边栏不变
- 只列自己名下的仓库（包括私有、fork、已归档）
- 超时留下的半截文件夹要删，但只删这次克隆新建的那一个
【默认假设】
- 克隆完自动加入监控（克隆就是为了同步）
- 不做浅克隆：浅克隆会让后面的推送和预演合并出问题
- 记住上次填的地址；第一次打开默认填 gh 登录的账号
- 进度只显示到每个仓库一级，不显示百分比
- 克隆超时用「联网超时」设置，大仓库可以把它调到 10 分钟
- 没装 gh、gh 没登录：改为只列公开仓库并给出提示，不直接拒绝
- gh 登录了但 git 没登录过 GitHub：私有仓库克隆失败，提示先在命令行里登录一次（不替用户运行 gh auth setup-git，因为它会改全局 git 配置）
【验收】
- 集成测试：用 make-test-repos 生成的本地裸仓库当"云端"，克隆到临时目录 → 自动加入监控 → 状态是已同步；目标文件夹已存在时拒绝克隆（白名单要允许测试用本地裸仓库的路径）
- 单元测试：clone 的允许 / 拒绝参数；gh 的允许 / 拒绝子命令；解析 gh 输出的 JSON 和公开接口返回的 JSON（用固定样本，不连真实 GitHub）；地址输入的解析（主页、用户名、单个仓库地址）
- 演示模式下：页签切换、列表、勾选、克隆进度、完成后主页出现新项目，都能走通
- npm run build 和 cargo test 全绿
- 待人工验收（写进 docs/待人工验收.md）：用真实 GitHub 账号列出私有仓库并克隆一个；没装 gh 的电脑上只列出公开仓库并显示提示
【线索】
- src/pages/AddProjectsPage.tsx：现有的扫描列表、勾选、底部「应用」条可以照着做
- src-tauri/src/git.rs：validate 白名单、runs_outside_repo（clone 不在仓库目录里运行）、ProxyPlan
- src-tauri/src/url.rs：去掉地址里的账号；前端的 repoShortName 在 src/lib/status.ts
- src-tauri/src/commands.rs：add_projects、net_lock、refresh_proxy
- src-tauri/src/scan.rs：判断一个文件夹是不是仓库
- scripts/make-test-repos.mjs：测试用的裸仓库
```
