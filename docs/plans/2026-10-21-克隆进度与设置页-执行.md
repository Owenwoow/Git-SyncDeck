- 克隆失败或超时时，只删除这次新建的目标文件夹
- 记住上次填的地址存在 `config.json` 的 `githubSource`

## 决定

- 组 1：git 进度只在有人要看时才加 `--progress`（同时去掉 `--quiet`，否则 push 不输出进度），刷新和手动"提交并推送"照旧安静执行。待拉取的项目，下载发生在"检查云端"的 fetch 里，pull 只是快进，所以界面把 fetch 的进度也写成"正在拉取 N 个提交 · 下载 45%"。
- 组 1：进度规则后端（`SyncProgressSnapshot::apply`）和前端（`syncProgress.ts` 的 `applyEvent`）各一份，规则相同；新增 `begin`（这一轮的项目清单）和 `retry`（等网络重试）两种进度事件，重试接着同一轮显示。
- 组 1：一键同步的弹窗关着时同步结束，右下角提示结果并可点「查看结果」（交接单没写，补上免得结果没人看）。
- 组 1：演示模式触发后台同步的方式：窗口切走 2 秒以上再切回来 = 解锁后同步；控制台 `__syncdeckDemo.autoSync(...)`。
- 组 2：设置页停在哪一类由 App 的 state 保存（「去更新」要能直接跳到「关于」）；"是否忙"的判断 `isAppBusy` 也算上正在克隆。
- 组 3：gh 只列、只读；没装或没登录时用 Windows 自带 curl.exe 请求公开接口，没加新的 Rust HTTP 依赖。克隆请求的文件夹名只许合法仓库名，防止目录穿越。
- 总控集成时修了组 3 的一个竞态：同一批同名仓库并发克隆时，失败的那个可能删掉另一个刚克隆好的文件夹；改成先 `create_dir` 占住目标文件夹。
