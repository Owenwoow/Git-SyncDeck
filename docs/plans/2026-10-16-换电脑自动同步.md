# 换电脑自动同步

- 状态：进行中
- 日期：2026-10-16
- 需求原话：
  1. 如何让这个程序的使用体验更无感？我可以让它保持在后台运行……家里的笔记本、家里的台式机（周五到周日）、学校的笔记本（周一到周五），中途会远程控制两台电脑同时使用……你得有一部分的冗余方案来应对冲突
  2. 有些设计可加入设置中自定义，某些内容可以选择关闭或者开启。obsidian 中的 git 完全可以参考过来。还有一个问题每次刷新同步，都会转很久
  3. 自动同步尽可能少一点……主要是在我要换电脑的情况下去同步，其他情况下手动同步就行；软件能不能改成如果我配置了系统代理，就用系统代理……前提是做这个操作完全能改变检查进度；检查同步可以改成并行处理吗；可以做开关；冲突合并暂存……预留报错提醒以及软件会提示一句话我复制给 ai……可以有无冲突自动合并，有冲突，转交给 ai
  4. 按这一版开工，顺序是：先做刷新提速和自动代理，再做托盘和离开/到达自动同步，最后做自动合并和「复制给 AI」
- 档位：大档，3 组（A 先做；B、C 等 A 合回后并行）（依据：每组 12~16 个文件，三组都改同步流程）
- 执行位置：本会话
- 额度：正常（5 小时 7%，每周 19%）
- 开工前已失败的测试：无

已定方案见 `docs/requirements.md` 第 7 节。

## 任务单

### 组 A：刷新提速 + 代理设置 + 同步选项结构

- 背景：Git SyncDeck（Tauri 2 + React 19 + Rust，见 CLAUDE.md）。用户反馈"每次刷新同步都会转很久"。实测（7 个项目，git 走 127.0.0.1:10808 代理）：本地 `git status` 每个约 50ms；每个项目连 GitHub 一次 1.9~4.8 秒；现在 4 个并行，一轮刷新约 8.5 秒；全部同时约 5 秒。体感慢的主要原因：`refresh_status` 要等所有项目都完成才返回，期间主页列表变灰不能点（`src/pages/HomePage.tsx:75`），按钮全禁用；一键同步又会把所有项目重新 fetch 一遍；联网超时 180 秒，代理卡住时整轮转 3 分钟。另外用户希望"配置了系统代理就用系统代理，或者给个配置代理的地方"。实测换 socks5 / http 代理速度没差别，不走代理会 21 秒超时失败，所以代理设置的意义是让 git 没配代理的电脑也能用。本组还要为后面两组铺一个"同步选项"结构，让 B、C 组不用改同一段代码。
- 要做：
  1. 并行数：`src-tauri/src/util.rs` 的 `CONCURRENCY` 从 4 改成 8。（验证：`cargo test` 通过）
  2. 刷新逐个出结果：`commands::refresh_status` 加参数 `on_event: Channel<RefreshProgressEvent>`，每个项目检查完立即发 `RefreshProgressEvent::Done { project, index, total }`（index 为完成顺序），最后仍返回完整列表。`model.rs` 和 `src/types/index.ts` 加对应类型；`src/api/tauri.ts` 的 `refreshStatus(onProgress?: (p: Project) => void)`，`src/mock/api.ts` 同签名（用延时逐个回调）。`src/state/projects.tsx` 刷新时边收边更新对应行，并对外提供"正在检查的项目 id 集合"；`HomePage.tsx` 刷新期间列表不再变灰、可以点开详情，「一键同步」在刷新期间也可点（后端会等这一轮检查结束，再复用刚检查过的结果）；`ProjectList.tsx` 正在检查的行在状态旁显示小转圈（`Loader2 animate-spin`）。（验证：`npm run build`；mock 模式浏览器里点刷新能看到逐行更新）
  3. 刷新用短超时：刷新时的 fetch 超时 = min(30 秒, 设置里的联网超时)；一键同步、推送、拉取仍用设置里的联网超时。在 `git.rs` 加常量，`ops::check` 接收超时参数或模式参数。（验证：单元测试或代码走读）
  4. 一键同步复用检查结果：`AppState` 在内存里记每个项目最近一次联网检查成功的时间（刷新和同步都记）。一键同步时，1 分钟内检查成功过的项目跳过 fetch，直接用本地 status 判断。引入 `ops::SyncOptions`（至少包含 `auto_commit: Option<String>`（提交信息，None 表示不自动提交）和 `skip_fetch: bool`），`ops::sync_one(dir, &SyncOptions)`；在 `commands.rs` 写**唯一的**构造函数 `fn sync_options_for(st, sp, commit_message) -> ops::SyncOptions`，`sync_all` 只通过它拿选项。后面 C 组会往 `SyncOptions` 加字段、改这个函数，B 组会复用它，所以 `sync_all` 循环体里不要再散落其他选项逻辑。"要不要跳过 fetch"的判断写成纯函数并加单元测试。（验证：`cargo test`；现有 `commands_flow`、`auto_commit` 等集成测试改成新签名后全绿）
  5. 代理设置：
     - 配置：`StoredSettings` 加 `proxy_mode: Option<String>`（`"auto"` / `"off"` / `"manual"`，None 等于 auto）、`proxy_url: Option<String>`；`Settings` / `SettingsPatch` 加 `proxy_mode`、`proxy_url`，`Settings` 另加只读的 `effective_proxy: Option<String>`（实际生效的代理地址，去掉账号密码，复用 `url.rs` 的去敏）和 `proxy_source`（`"git"` / `"system"` / `"manual"` / `"none"`）。前端类型、两套 API 同步改。
     - 生效方式：只对 SyncDeck 调用的 git 生效，**不改用户的全局 git 配置**。在 `git.rs` 用和联网超时类似的全局变量保存"代理覆盖"：不覆盖 / 使用某地址（`run_git` 加 `-c http.proxy=<地址>`）/ 禁用（让 git 完全不走代理：覆盖 git 配置和 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 等环境变量，大小写都要处理，具体做法自己验证）。
     - 自动模式：git 自己配了代理（`http.proxy` 配置，或上述环境变量）→ 不覆盖，`proxy_source = "git"`；没配而 Windows 系统代理开着（`HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 的 `ProxyEnable = 1` 和 `ProxyServer`）→ 使用系统代理，`proxy_source = "system"`；都没有 → `"none"`。`ProxyServer` 可能是 `host:port`，也可能是 `http=h:p;https=h:p;socks=h:p`：优先 https=，其次 http=，再次不带前缀的，最后 socks=（转成 `socks5://`）；没写协议的补 `http://`。用了 PAC（AutoConfigURL）的情况不支持，当作没有系统代理。读注册表用 `winreg` crate（放在 `[target.'cfg(windows)'.dependencies]`），解析写成纯函数并加单元测试。读 git 自己的 `http.proxy` 时，`run_git` 现在要求目录是仓库根，可以加一个不需要仓库的只读例外（如 `config --global --get http.proxy`），要在白名单里补单元测试；或者用其他不新增子进程风险的办法，自己选。
     - 手动模式：校验地址，只接受 `http://`、`https://`、`socks5://`、`socks5h://` 开头且有主机和端口的；不合法时 `save_settings` 返回中文错误。
     - 每轮刷新 / 同步开始前重新解析一次（用户可能中途开关代理软件），保存设置时也重新解析。
     - 界面：设置页"常规"一节、联网超时卡片下面加"代理"卡片：三个选项（自动 / 不用代理 / 手动填写），手动时显示输入框（失焦或回车保存）；下面一行说明当前实际情况，如"当前：使用 git 自己的代理 socks5://127.0.0.1:10808""当前：使用系统代理 http://127.0.0.1:10808""当前：不使用代理"；再加一行灰字"只影响 https 地址的仓库，SSH 地址的仓库不受影响"。卡片样式照抄同页现有卡片。
     （验证：单元测试；`npm run build`；mock 模式下设置页能切换三种模式）
  6. 测试：现有集成测试改成新签名；新增：`refresh_status` 对每个项目各发一次 Done 事件、最终列表和事件一致；跳过 fetch 的判断函数、代理解析函数、代理参数拼接的单元测试。（验证：`cd src-tauri; cargo test` 全绿）

### 组 B：托盘、开机自启、离开/到达自动同步、通知、本机名称

- 背景：用户三台电脑轮流用，希望 SyncDeck 常驻后台，**只在换电脑的时刻**自动同步，平时手动。完整决定见 `docs/requirements.md` 第 7 节（必读）。组 A 已把一键同步改成通过 `commands::sync_options_for` 构造 `ops::SyncOptions`，并加了刷新进度事件；组 C 同时在改 `ops.rs` 的同步逻辑（自动合并、提交前检查）和设置页的另一节，本组不碰那些。
- 要做：
  1. 依赖与插件：`tauri` 开 `tray-icon` 特性（需要的话加 `image-png`）；加 `tauri-plugin-autostart`、`tauri-plugin-notification`、`tauri-plugin-single-instance`；Windows 系统事件需要的 `windows` 或 `windows-sys` crate（`[target.'cfg(windows)'.dependencies]`）；`capabilities/default.json` 补权限；前端需要的插件 JS 包。（验证：`cargo build` 通过）
  2. 后台运行：只允许一个实例，再次启动时把已有窗口显示到前面；关窗口时，如果设置"关窗口时隐藏到托盘"（默认开）就隐藏而不退出；开机自启（默认开，用 autostart 插件，带 `--autostart` 参数启动时窗口不显示，只有托盘）。调试构建（`debug_assertions`）下不要自动注册开机自启，只在用户手动打开开关时注册，免得把开发版注册进去。（验证：手动；写进待人工验收）
  3. 托盘（建议新文件 `src-tauri/src/tray.rs`）：图标颜色——红：有项目分叉、有异常标记或检查失败；黄：有项目待推送或有未提交改动；蓝或转圈：正在同步；绿：其他。图标可以在代码里用 RGBA 画，也可以放进 `src-tauri/icons/`。悬停文字如"Git SyncDeck · 7 个项目已同步"。菜单：立即同步、打开主界面、暂停自动同步（到明天）/ 恢复自动同步（文字随状态切换）、退出（真正退出）。左键单击打开主界面。每次项目状态变化后更新图标。
  4. 同步引擎复用：把 `sync_all` 的主体抽成后端可调用的函数（例如 `run_sync(st, 项目范围, 进度回调)`），前端的 `sync_all` 命令和后台自动同步都用它，`syncing` 标记和 `net_lock` 的语义不变，选项一律通过 `sync_options_for` 拿。后台发起的同步结束后，用 Tauri 事件通知前端（例如 `projects-changed`，带最新项目列表；`auto-sync-finished`，带结果和触发原因），前端 `src/api/` 两套实现各加一个监听函数，`src/state/projects.tsx` 收到就更新列表。
  5. 系统事件（建议新文件 `src-tauri/src/sysevents.rs`，`cfg(windows)`）：起一个隐藏的顶层窗口（注意 message-only 窗口收不到广播和关机消息）和它自己的消息循环线程：
     - `WTSRegisterSessionNotification`：锁屏 → 离开；解锁 → 到达
     - `WM_POWERBROADCAST`：`PBT_APMSUSPEND` → 离开（尽力而为，不阻塞）；`PBT_APMRESUMEAUTOMATIC` / `PBT_APMRESUMESUSPEND` → 到达（唤醒后网络可能还没好：失败时等 15 秒左右重试一次）
     - `WM_QUERYENDSESSION` / `WM_ENDSESSION`：关机、重启、注销 → 离开；用 `ShutdownBlockReasonCreate` 显示"Git SyncDeck 正在同步…"，**最多等 30 秒**，同步完或超时就放行，绝不无限阻止关机
     - 程序启动本身算一次"到达"
  6. 调度（建议新文件 `src-tauri/src/autosync.rs`）：
     - 把"这次要不要做"写成纯函数并加单元测试：输入触发类型（离开：关机/锁屏/睡眠；到达：启动/唤醒/解锁/托盘立即同步）、当前时间、上次同一种同步的时间、暂停到的时间、各开关；规则：同一种（离开 / 到达）10 分钟内只做一次（托盘"立即同步"和关机不受这条限制）；暂停到明天 = 暂停到本地时间次日 00:00；对应开关关着就不做
     - 离开：先对所有项目做本地检查（不联网），只挑"待推送"或"有未提交改动且开了自动提交"的项目去同步；一个都没有就完全不联网。这个挑选逻辑也要有测试（可以用 `make-test-repos.mjs` 生成的临时仓库做集成测试）
     - 到达：对所有项目跑一遍同步
     - 已经有一轮同步在跑时：到达类直接跳过；关机要等它结束后再做自己的离开同步（总共仍不超过 30 秒）
     - 定时检查云端（设置，默认关）：打开后每 30 分钟刷新一次（fetch + status，不拉取），只更新列表和托盘图标
     - 前端启动时现在会自动刷新一次（`src/state/projects.tsx`）。打开了"启动时同步"的话，改成由后端做到达同步，前端只显示本地状态并等事件，避免同时跑两轮
  7. 通知：只在后台发起的同步（包括托盘"立即同步"）之后发，窗口里点的一键同步不发（结果对话框已经显示）。有失败或冲突时发一条（"2 个项目需要处理：A、B"，设置"出错或冲突时通知"默认开）；成功且确实推送或拉取了东西时发一条（设置"同步成功时通知"默认关）。
  8. 本机名称：设置加 `host_name`（空 = 用 `COMPUTERNAME`），提交信息模板的 `{host}` 用它；`util.rs` 里取电脑名的地方改成优先用这个设置。设置页"自动提交"一节的模板卡片里加"本机名称"输入框（失焦或回车保存），预览随之变化。
  9. 设置页：在"常规"之后新增一节"自动同步"：开机自启、关窗口时隐藏到托盘；离开时同步：关机 / 锁屏 / 睡眠（三个开关，默认都开）；到达时同步：启动 / 唤醒 / 解锁（三个开关，默认都开）；定时检查云端（默认关）；通知：同步成功时（默认关）、出错或冲突时（默认开）。开关用现有 `Checkbox` 或新增 shadcn `switch` 组件，卡片样式照抄同页。暂停中时，主页标题栏或侧边栏显示"自动同步已暂停到 明天 00:00"和「恢复」按钮。新设置字段：`StoredSettings` 用 `Option` + 默认值，旧 `config.json` 能正常读。

### 组 C：分叉时预演合并、「复制给 AI」、先提交后合并、提交前检查

- 背景：用户多台电脑可能改同一个项目。已定（见 `docs/requirements.md` 第 7 节，必读）：分叉时先用 `git merge-tree --write-tree` 在内存里预演，无冲突就自动合并并推送；有冲突什么都不动（不开始合并、不碰工作区），项目标红，给一段能复制给 AI 的提示词，由用户和 AI 解决。自动提交改成"先在本地提交，再按分叉处理"。因为离开电脑时会在没人看着的情况下自动提交，所以要加提交前检查（大文件、疑似密钥文件），防止把密钥推进公开仓库。安全红线不变：不强推、不 rebase、不 reset、不 stash；所有 git 子进程只能从 `git.rs` 的 `run_git` 创建，受白名单约束。组 A 已引入 `ops::SyncOptions` 和 `commands::sync_options_for`；组 B 同时在做托盘和后台自动同步（会复用同步引擎、改设置页的另一节），本组不碰 B 的文件。
- 要做：
  1. 白名单（`git.rs` 的 `validate`）：允许 `merge-tree --write-tree --name-only <a> <b>`（参数形式自己定，但只允许预演需要的）；允许 `merge --no-edit -m <信息> <上游引用>`（不许 `--squash`、`-s`、`-X`、`--allow-unrelated-histories` 等其他选项）；允许 `merge --abort`。单元测试覆盖允许和拒绝的形式。（验证：`cargo test --lib git::`）
  2. 分叉处理（`ops.rs`）：`SyncOptions` 加 `auto_merge: bool` 和合并提交信息（`"自动合并：来自 {host}"`，`{host}` 用和提交模板同一个取电脑名的来源，在 `sync_options_for` 里拼好，本组不改 `util.rs`）。`sync_one` 遇到分叉且工作区干净、`auto_merge` 打开时：预演 → 无冲突就正式合并 → 推送 → 结果 `Merged`（`commits` = 推送的提交数）；有冲突 → 记为异常，原因写清楚（如"本地和云端改了同一处，自动合并会冲突：README.md、src/App.tsx。没有改动任何文件，可在详情里「复制给 AI」"）；正式合并万一失败 → `merge --abort` 后记为异常。git 版本低于 2.38（不支持 `--write-tree`）→ 记为异常并说明需要升级 git，不合并。`auto_merge` 关着 → 和现在一样记为异常。
  3. 自动提交改顺序（`auto_commit_and_push`）：冲突文件、正在 merge/cherry-pick/revert 的检查保留 → 提交前检查（第 4 项）→ `add -A` → `commit` → 之后如果领先就推送，分叉就走第 2 项的预演合并。去掉原来"落后时先 `pull --ff-only` 再提交""分叉时不提交"的逻辑。
  4. 提交前检查（只用于自动提交，手动"提交并推送"不检查）：用 `git status --porcelain=v2 -z --untracked-files=all` 列出将要提交的文件（`.gitignore` 已由 git 处理），检查：单个文件大小超过上限（设置，默认 50 MB）；文件名像密钥：`.env`、`.env.*`（但放过 `.env.example`、`.env.sample`、`.env.template`）、`*.pem`、`*.key`、`*.p12`、`*.pfx`、`id_rsa`、`id_dsa`、`id_ecdsa`、`id_ed25519`。命中 → 不提交，记为异常，列出命中的文件和原因，并提示加进 `.gitignore`。设置可关（默认开）。判断规则写成纯函数加单元测试。
  5. 设置：`StoredSettings` / `Settings` / `SettingsPatch` 加 `auto_merge`（默认开）、`precommit_check`（默认开）、`big_file_limit_mb`（默认 50），新字段加在结构体末尾，`Option` + 默认值，旧 `config.json` 能读；前端类型、两套 API 同步。设置页在"自动提交"一节之后新增一节"冲突与提交检查"：无冲突时自动合并、提交前检查、大文件上限（MB）。
  6. 冲突文件和「复制给 AI」：`DiagnosticInfo` 加 `conflict_files: Vec<String>`（分叉时用 merge-tree 预演算出来，否则为空），以及云端最近的提交（`recent_remote_commits`，最近 3 个，复用 `recent_commits` 的写法）。`src/lib/diagnostic.ts` 加生成提示词的函数，格式参考：
     ```
     我的 Git 项目「Git-SyncDeck」（E:\Code\Git-SyncDeck，分支 main）在两台电脑上改了同一处，自动合并失败。
     本地比云端多 2 个提交、少 1 个提交；冲突文件：README.md、src/App.tsx。
     本地最近的提交：……
     云端最近的提交：……
     请一步一步教我在这台电脑上解决冲突并推送，不要用 force push、reset 或 rebase。
     ```
     项目详情（`ProjectDetailSheet.tsx` / `ProjectActions.tsx`）在分叉状态下显示「复制给 AI」按钮，和"复制诊断文本"放在一起；一键同步对话框（`SyncDialog.tsx`）里失败原因是分叉/冲突的项目也给这个按钮。复制后提示"已复制，粘贴给 AI 即可"。
  7. 结果类型与文案：`SyncOutcome` 加 `Merged`（前端 `"merged"`，"已自动合并并推送 N 个提交"），算同步成功；`src/lib/status.ts` 里分叉的说明在自动合并打开时改成"一键同步会先预演合并，没有冲突就自动合并"；mock 实现能演示合并成功和冲突两种情况。
  8. 测试（`scripts/make-test-repos.mjs` 加场景，`src-tauri/tests/` 加集成测试）：① 分叉、改的不同文件 → 一键同步后已合并并推送，云端最新提交是合并提交，状态已同步；② 分叉、改了同一处 → 记为异常、原因含冲突文件名、本地和云端提交都没变、工作区干净、没有 MERGE_HEAD；③ 开了自动提交、有改动且落后、改的不同文件 → 先提交再合并，推送成功；④ 开了自动提交、有改动且落后、改了同一处 → 本地多了一个自动提交、项目变为分叉并记为异常、云端没变；⑤ 有 `.env` 未被忽略 → 不提交；⑥ 大文件超过上限（测试里把上限设小，比如 1 MB，造一个 2 MB 的文件）→ 不提交；⑦ 关掉自动合并 → 分叉照旧记为异常。现有测试里和旧行为冲突的期望（如原来的场景 8、9，以及场景 5"分叉"在一键同步后的结果），按新行为更新，并在报告里逐条列出改了哪些期望、为什么。
