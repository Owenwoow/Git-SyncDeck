# Git SyncDeck 需求说明

## 1. 背景与目标

用户有台式机和笔记本两台 Windows 电脑，通过 GitHub 同步多个本地项目。离开一台电脑前要把所有项目的改动推上去，到另一台电脑再全部拉下来，逐个操作容易漏。

本工具在一个界面里展示所有项目的同步状态，并提供"一键同步"：能自动处理的（推送/拉取）自动处理，不能自动处理的列出原因并给出处理入口。

**分阶段**
- 第一阶段（当前）：GUI Demo，全部假数据，用来反复调整界面。
- 第二阶段：界面定稿后，把 `src/api/` 的实现换成 Tauri 命令，接入真实 git 操作。

## 2. 同步状态（7 种）

| 状态 | 含义 | 一键同步时 | 排序 |
|---|---|---|---|
| 分叉 | 本地和云端都有对方没有的提交 | 异常，不处理 | 1 |
| 有未提交改动 | 工作区或暂存区有改动 | 异常，不处理 | 2 |
| 未关联云端 | 没有远程仓库，或当前分支没有上游 | 异常，不处理 | 3 |
| 待拉取 | 云端有新提交 | 自动拉取 → 已同步 | 4 |
| 待推送 | 本地有新提交 | 自动推送 → 已同步 | 5 |
| 同步中 | 一键同步过程中的过渡状态 | — | 6 |
| 已同步 | 本地与云端一致 | 再确认一遍 | 7 |

- 每种状态用 颜色 + 图标 双重区分，浅色/深色各一套色值。
- 判定优先级（第二阶段按此实现）：没有远程 / 没有上游 / detached HEAD / 上游已不存在 → 未关联云端；工作区或暂存区有改动（含未跟踪）→ 有未提交改动；领先且落后 → 分叉；只领先 → 待推送；只落后 → 待拉取；其余 → 已同步。详情里仍展示全部事实。
- 检查失败（如断网时 fetch 失败）不是一种状态：保留上一次的状态，另外显示"检查失败：原因"。

## 3. 页面与功能

### 3.1 主页
- 顶部：标题、「刷新状态」、「一键同步」（同步中禁用）。
- 概览：项目总数 / 已同步 / 需处理（= 总数 − 已同步，附"其中 X 个可自动同步，Y 个需手动处理"）。
- 工具栏：名称搜索；状态筛选（全部 + 6 种状态，带数量）。
- 列表：项目名、分支、本地路径、GitHub 仓库（owner/repo）、状态、上次同步时间；被跳过的异常项目多一行原因。需要处理的排在前面。
- 空状态：没有项目 → 引导去添加；没有匹配 → 清除筛选。

### 3.2 项目详情（右侧抽屉）
- 状态说明（这个状态意味着什么、一键同步会怎么做）
- 领先 / 落后的提交数
- 分支 → 上游、远程仓库地址、上次同步时间
- 未提交的文件：按 已暂存 / 未暂存 / 未跟踪 分组，带变更类型标记
- 异常状态时底部提供：复制诊断文本、提交并推送、打开 ▾（不提供"本次跳过"）

### 3.3 一键同步（模态对话框）
- 进行中：进度条 + 每个项目的实时状态（等待中 → 正在推送 3 个提交 · 上传 45% → 结果），推送、拉取时细到 git 的百分比。
- 进行中也可以关掉弹窗，同步照常进行（v0.6.0 起；原先不可关闭）：主页的「一键同步」按钮变成进度按钮（底色按总进度填充，文字"正在同步 3/7"），点它重新打开；标题下一行写"一键同步 · 正在推送 某项目 上传 45%"；列表里正在处理的那一行显示"同步中 45%"。弹窗关着时同步结束，右下角提示结果，可点「查看结果」。
- 结束后：汇总"N 个已同步 · M 个异常"，随后续处理实时更新。
- 每个异常项目：原因 + 四个操作
  - 复制诊断文本：项目信息 + 模拟 `git status -sb` + 目标，可直接粘贴给 AI
  - 提交并推送：仅"有未提交改动"且有上游时可用，其余置灰并提示原因
  - 本次跳过：主页保留异常标记和原因
  - 打开 ▾：终端 / VS Code
- 关闭时未处理的异常项等同于跳过。

### 3.4 添加项目
- 进入页面自动扫描默认代码目录（含子目录）；「选择目录…」换目录后重新扫描。
- 每个仓库带复选框，已监控的默认勾选；勾选变化先暂存，底部显示"将添加 X 个、取消监控 Y 个"，点「应用」才生效，可「撤销更改」。
- 搜索框按名称、路径、仓库（owner/repo）过滤，只影响显示，不影响勾选。
- v0.6.0 起页面顶部有两个页签：本地扫描（以上内容）/ 从 GitHub 克隆（见第 8 节）。

### 3.5 设置
- 排版：左边是分类目录（常规 / 网络 / 自动同步 / 提交与合并 / 外观 / 关于），点哪类右边只显示那一类；"目录 + 内容"整块在主内容区居中，最宽约 1000px。设置项一行一项：左边标题和说明，右边控件（开关、分段选择、按钮、短输入框）；要填较长文字的（默认代码目录、代理地址、提交信息模板、本机名称）放到下一行占满宽度。窗口窄时分类目录仍显示文字。首次打开显示「常规」，切到别的页面再回来停在上次看的分类（只记在内存里，重启后回到「常规」）。
- 各分类：
  - 常规：默认代码目录（选择后立即保存）
  - 网络：联网超时（点选即保存）、代理（自动 / 不用代理 / 手动填写）
  - 自动同步：后台运行（开机自启、关窗口时隐藏到托盘、**退出 SyncDeck** 按钮）、离开这台电脑时、回到这台电脑时、检查云端、通知、暂停自动同步
  - 提交与合并：提交信息模板（失焦或回车保存，带预览和「恢复默认」）、本机名称、无冲突时自动合并、提交前检查和大文件上限
  - 外观：主题，浅色 / 深色（首次启动跟随系统，之后记住选择）
  - 关于：当前版本、检查更新、下载并安装（完成后自动重启）
- **退出 SyncDeck**：和托盘菜单「退出」同一个逻辑（`quit_app` 命令）。没在做事就直接退出；正在同步（一键同步进行中、后台自动同步进行中或有项目处于"同步中"）时先弹确认"退出会中断正在进行的同步，确定退出吗？"。演示模式只弹提示"演示模式不会真的退出"。
- 有新版本时，侧边栏设置图标和设置页目录的「关于」旁都显示小圆点；启动时更新提示的「去更新」直接打开设置的「关于」。

### 3.6 通用
- 简体中文；左侧窄侧边栏；默认窗口 1100×720，最小 800×560。
- 窗口宽度 < 960px 时侧边栏只显示图标；内容区变窄时隐藏"GitHub 仓库"列。

## 4. 明确不做
取消同步、提交历史、部分文件提交、"跟随系统"主题选项、按固定间隔的后台自动提交（自动同步只在换电脑的时刻触发，见第 7 节）、自动解决冲突（有冲突一律交给用户，可复制提示词给 AI）、冲突时推送备份分支、rebase / 压缩提交。

> v0.4.0 起，托盘、系统通知、定时检查云端（默认关）改为要做，见第 7 节。

## 5. 第二阶段实现决定

| 问题 | 决定 |
|---|---|
| "待拉取"需要先 fetch | 启动时先做本地检查（不联网）立即显示，随后后台自动刷新一次；刷新 = fetch + status，最多 4 个并行（v0.4.0 起 8 个，逐个出结果） |
| 拉取方式 | `git pull --ff-only --no-rebase --no-autostash`，不是快进就判为分叉（v0.4.0 起分叉时先预演合并，见第 7 节） |
| 推送方式 | `git push <远程> refs/heads/<分支>:refs/heads/<上游分支>`，永不强推 |
| 网络失败、认证失败、推送被拒 | 计入异常，原因为 git 的 stderr 原文（去掉 URL 中的账号信息） |
| 凭据 | 只用已保存的凭据：`GIT_TERMINAL_PROMPT=0`、`GCM_INTERACTIVE=never`，没有就报错，不弹窗 |
| 提交并推送时云端也有新提交 | 提交保留在本地，停止推送并报告，项目变为分叉 |
| 异常标记何时清除 | 下次同步成功、提交并推送成功，或刷新时检测到已同步 |
| 只检查当前分支 | 是；其他分支的未推送提交暂不提醒（可作为后续功能） |
| 特殊仓库状态 | detached HEAD、上游已删除 → 未关联云端；合并冲突中的文件计为未提交改动 |
| 存储 | `%APPDATA%\com.gitsyncdeck.desktop\config.json`，写入时先写临时文件再改名 |
| 一键同步进度 | Rust 端通过 Tauri 2 Channel 推送 `SyncProgressEvent`，并行时 index 为完成顺序 |
| 诊断文本 | 路径、分支、上游、领先/落后、三类文件名、最近 3 次提交，不含文件内容和 diff |

## 6. 自动提交与应用内更新（v0.2.0）

| 问题 | 决定 |
|---|---|
| 自动提交何时触发 | 点"一键同步"时；v0.4.0 起换电脑时的自动同步也会触发（见第 7 节），仍不做按固定间隔的后台提交 |
| 哪些项目 | 每个项目单独开关（项目详情里），默认关；开关存在 config.json 的 `autoCommit` |
| 提交信息 | 模板默认 `自动同步：{date} 来自 {host}`，`{date}` = 本地时间 `YYYY-MM-DD HH:mm`，`{host}` = `COMPUTERNAME`；同一轮一键同步所有项目共用同一个时间 |
| 云端有新提交 | 先 `pull --ff-only`，成功后再提交推送；git 拒绝就不提交，记为异常（v0.4.0 起改为先提交再预演合并，见第 7 节） |
| 不提交的情况 | 有冲突文件；存在 MERGE_HEAD / CHERRY_PICK_HEAD / REVERT_HEAD；本地和云端分叉；没有上游（v0.4.0 起分叉不再阻止提交，另加提交前检查，见第 7 节） |
| 推送失败 | 提交保留在本地，记为异常 |
| 同步结果 | 新结果类型 `committed`（已自动提交并推送），算作同步成功 |
| 应用内更新 | `tauri-plugin-updater`，读 GitHub Releases 的 `latest.json`；启动时静默检查一次，设置页可手动检查；Windows 用 passive 安装模式，装完重启 |
| 更新签名 | 私钥在开发机 `%USERPROFILE%\.tauri\git-syncdeck.key`（无密码），发布时由 GitHub Secret `TAURI_SIGNING_PRIVATE_KEY` 提供；公钥写在 `tauri.conf.json` |

## 7. 换电脑自动同步（v0.4.0）

背景：三台电脑轮流用（家里笔记本、家里台式机周五到周日、学校笔记本周一到周五），偶尔远程控制让两台同时开着。同步主要发生在换电脑的时候，平时手动同步就够，自动同步要尽量少。

| 问题 | 决定 |
|---|---|
| 自动同步什么时候发生 | 只在换电脑的两个时刻：**离开**（锁屏）和**到达**（开机/程序启动、从睡眠唤醒、解锁）。平时不自动做事 |
| 离开时做什么 | 先在本地检查（不联网），只对"有东西要推"的项目联网：领先（待推送）的推送；有未提交改动且开了自动提交的，提交后推送。没有要推的就完全不联网 |
| 到达时做什么 | 对所有项目跑一遍一键同步的逻辑（拉取、补推上次没推完的） |
| 频率限制 | 同一种自动同步（离开 / 到达）10 分钟内只做一次 |
| 关机、睡眠时 | 不同步（v0.5.0 起）。原先关机最多等 30 秒、睡眠尽力而为，实际用起来不可靠，改为靠下次开机、唤醒或解锁时的到达同步补推、拉取 |
| 自动提交 | 沿用每个项目的"自动提交"开关，手动一键同步和自动同步都生效 |
| 托盘 | 常驻托盘；图标绿 = 都已同步，黄 = 本机有改动还没同步，红 = 有冲突或出错；菜单：立即同步、打开主界面、暂停自动同步（到明天）/ 恢复自动同步、退出 |
| 后台运行 | 开机自启（启动时直接进托盘）、关窗口时隐藏到托盘，都可以在设置里关；只允许运行一个实例 |
| 定时检查云端 | 默认关；打开后每 30 分钟检查一次，只在托盘提示，不自动拉取 |
| 通知 | 同步成功默认不通知；出错或冲突默认通知，每次只通知一次 |
| 本机名称 | 设置里可填（家里笔记本 / 台式机 / 学校笔记本），用于提交信息的 `{host}`；不填用 `COMPUTERNAME` |
| 分叉时 | 先用 `git merge-tree --write-tree` 预演（只在内存里算，不碰工作区）。无冲突 → 正式合并（提交信息"自动合并：来自 {host}"）后推送；有冲突 → 什么都不动，项目标红，通知一次。可在设置里关掉自动合并，关掉后分叉照旧记为异常 |
| 自动提交的顺序 | 先在本地提交，再按上一行处理（以前是先快进拉取再提交，分叉时不提交） |
| 冲突交给 AI | 项目详情和一键同步结果里有「复制给 AI」：复制一段现成的提示词（项目名、路径、分支、领先/落后、冲突文件、两边最近的提交，并要求不用 force push / reset / rebase） |
| 提交前检查 | 自动提交前检查：单个文件超过 50 MB（可改）或疑似密钥文件（如 `.env`、`*.pem`、`*.key`、`id_rsa`）没被忽略 → 这次不提交，记为异常并说明原因。设置里可以关 |
| 刷新速度 | 所有项目同时检查（实测 7 个项目从约 8.5 秒降到约 5 秒）；每个项目检查完就显示，列表不再整体变灰；刷新时 fetch 超时 30 秒；一键同步复用 1 分钟内刚检查过的结果，不重复 fetch |
| 代理 | 设置里选：自动（默认）/ 不用代理 / 手动填写，只对 SyncDeck 调用的 git 生效，不改全局 git 配置。自动 = git 自己配了代理（配置或环境变量）就用 git 的；没配而 Windows 系统代理开着，就带上系统代理。只影响 https 地址的仓库，SSH 地址不受影响 |

### 后台同步的进度（v0.6.0）

参考 GitHub Desktop：后台同步时也能随时看到进度，不自动弹窗。

| 问题 | 决定 |
|---|---|
| 进度在哪里看 | 主页「一键同步」按钮在后台同步时变成进度按钮（"后台同步 3/7"，底色按总进度填充），点开是和一键同步一样的进度弹窗，随时可以关；标题下一行写"解锁后同步 · 正在推送 某项目 上传 45%"，同时处理好几个时后面加"等 3 个"；等网络重试时写"等待网络，15 秒后重试 N 个项目" |
| 细到什么程度 | git 的百分比：fetch / push / pull 带 `--progress`，边运行边解析。阶段只显示用户关心的：上传、下载、处理差异；统计、压缩归到"准备中"。git 的提示跟随系统语言，中英文都认 |
| 总进度 | （已完成的项目数 + 正在处理的项目各自的完成度）÷ 项目总数；每个项目的完成度只增不减 |
| 窗口中途打开 | 后端记着这一轮到现在的进度，窗口打开时补上 |
| 结束后 | 只保留最近一次的结果（在内存里，重启后没有）：主页标题下写"上次后台同步：10:32 解锁后 · 已推送 2 个 · 1 个需要处理"，点开就是一键同步那样的结果弹窗，异常可以直接处理 |
| 托盘 | 悬停文字"正在同步 3/7" |
| 不做 | 同步记录列表；结果写进配置文件；定时检查云端显示进度（它只是看一眼）；取消正在进行的同步（关掉弹窗不等于取消） |

### 实现时补充的决定

| 问题 | 决定 |
|---|---|
| 托盘「立即同步」 | 算手动操作：不受暂停、开关和 10 分钟限制 |
| 暂停期间 | 定时检查云端也不做（暂停 = SyncDeck 不自己联网做事） |
| 锁屏时已经有一轮在跑 | 直接跳过（正在跑的那一轮会推送） |
| 唤醒 / 解锁时有离开同步还在跑 | 先等它结束（最多 2 分钟），免得被睡眠打断的锁屏那一轮挡掉到达同步 |
| 联网失败重试 | 只用在启动和唤醒，等 15 秒左右只重试检查失败的项目 |
| 通知 | 一轮最多一条，有失败只发失败那条 |
| 离开时挑哪些项目 | 待推送；有未提交改动且开了自动提交；打开自动合并时还有分叉的 |
| 托盘颜色 | 待拉取、未关联云端算绿，只写在悬停文字里 |
| 系统事件窗口 | 隐藏的 0×0 顶层窗口（message-only 窗口收不到电源广播） |
| 单实例、开机自启 | 单实例只在发布版启用；调试版的开机自启项叫"Git SyncDeck (dev)"，调试版不会自动注册 |
| 自动提交后又合并 | 结果记为 `merged`（已自动合并并推送），提交数包含自动提交和合并提交 |
| 自动合并的防护 | 分支配了 `branch.<分支>.mergeoptions` 时不自动合并；合并后核对没有 MERGE_HEAD、两个父提交、树哈希都和预演一致才推送，不一致就不推送并记为异常 |
| 大文件上限 | 1 ~ 2048 MB，配置里超出范围按默认 50 |
| 代理细节 | 按网址的 `http.<网址>.proxy` 也算"git 自己配了代理"，"不用 / 手动"时一并覆盖；只设了 `HTTP_PROXY` 不算（git 对 https 不用它）；用系统代理时把系统绕过列表转成 `NO_PROXY`；手动地址可带账号密码，显示时去掉 |

## 8. 从 GitHub 克隆（v0.6.0）

背景：换新电脑或想把 GitHub 上的某个仓库放到本机时，要先到网页上复制地址、开命令行 `git clone`，再回来添加项目。希望填一次 GitHub 账号主页，列出自己的仓库，勾选后直接克隆到默认代码目录并加入监控。

| 问题 | 决定 |
|---|---|
| 入口 | 「添加项目」页顶部两个页签：本地扫描（原有）/ 从 GitHub 克隆 |
| 输入 | 一个输入框，接受账号主页（`https://github.com/用户名`、`github.com/用户名`、末尾带 `/`）、纯用户名、单个仓库地址（`https://github.com/用户/仓库`、带 `.git`、`git@github.com:用户/仓库.git`）。用户名只允许字母、数字和 `-`（不以 `-` 开头），仓库名允许字母、数字和 `- _ .`，其他报中文错误。填账号 = 列出名下全部仓库，填仓库 = 只列这一个。第一次打开优先填上次的输入，没有就填 gh 当前登录的账号；输入保存在 `config.json` 的 `github_source` |
| 列哪些仓库 | 只列自己名下的（含私有、fork、已归档）。排序：非 fork 非归档在前，各自按最近推送时间倒序。列表有搜索框（仓库名、描述）；旁边只有一个“筛选”菜单，包含“仅看可克隆”“隐藏 fork”“隐藏已归档”，默认全部关闭、不持久化，与搜索取交集。按钮显示启用开关数量，菜单可清除筛选，零匹配时可清除搜索和筛选。筛选只改变显示、不取消勾选，全选只作用于可见且可克隆的项；底部显示总选择数及隐藏的选择数 |
| 私有仓库怎么列 | 调用 GitHub CLI（gh）：`gh repo list <账号> --limit 1000 --json …`（单个仓库用 `gh repo view`）。SyncDeck 不碰令牌，守住"不读写凭据"；代价是每台电脑要装一次 gh 并 `gh auth login` |
| gh 不可用时 | 没装 gh、gh 没登录（`gh api user` 失败）、gh 列仓库失败，都退到 GitHub 公开接口（不带任何凭据），用 Windows 自带的 `curl.exe` 请求，只能看到公开仓库，列表上方的提示条说明原因：没装写"装好 GitHub CLI（gh）并运行 gh auth login 后能看到私有仓库"，没登录写"gh 还没登录：运行 gh auth login 后能看到私有仓库"，gh 失败写出失败原因 |
| gh 和 curl 的白名单 | gh 只允许三种完整写法：`api user --jq .login`、`repo list <账号> --limit 1000 --json <固定字段>`、`repo view <账号/仓库> --json <固定字段>`，不许 auth、`auth setup-git`、`repo clone`、api 的其他路径。curl 只允许 `-sS --fail --max-time 30` 加固定的两个请求头，地址只能是 `https://api.github.com/users/<账号>/repos?per_page=100&type=owner&sort=pushed&page=<1~10>`（最多翻 10 页，不足 100 条就停）或 `https://api.github.com/repos/<账号>/<仓库>`。两者都不弹窗、有 30 秒超时、超时终止，代理按设置里的代理模式（使用代理时设 `HTTPS_PROXY` / `HTTP_PROXY`，不用代理时去掉这些环境变量，curl 加 `-x` / `--noproxy *`） |
| 已在本地 | 默认代码目录、本次选择的保存目录下扫描到的仓库，以及监控清单里的项目，路径去重后，只要远程地址规范化后相同（去账号、小写、去 `.git` 和末尾 `/`、`git@github.com:a/b` 转成 `github.com/a/b`、去协议），就标“已在本地”，不能勾选。本次保存目录下已有同名文件夹的标“文件夹已存在”，也不能勾选，不覆盖 |
| 克隆到哪 | “保存到”初始使用设置中的默认代码目录，可点“更改…”打开系统文件夹选择器，为本批仓库选择一个共用父目录；目标为父目录\仓库名，不逐仓库指定或重命名。不保存临时目录、不修改设置，整批结束恢复默认。路径单行省略、悬停可查看完整内容，底部按钮只显示“克隆 N 个”。选择取消不改变状态，检查失败保留原目录；成功后更新目标和占用，保留仍可克隆的勾选、移除失效项并提示。换目录只做本地检查，不重新请求 GitHub；检查期间不可克隆，开始时再次校验父目录为存在的绝对目录，并冻结本批路径。用 https 的 `clone_url`；完整参数只有 `git clone --progress <地址> <目标>`，git 白名单拒绝其他参数和 `ext::` 这类传输；地址只能是 `https://` 或本机绝对路径（测试用本地裸仓库） |
| 克隆过程 | 和刷新、一键同步互斥（`net_lock`）；最多同时 3 个；每个仓库显示 等待 / 克隆中 · 下载 45% / 完成 / 失败（原因），一个失败不影响其他；全部结束后弹提示汇总，主页刷新出新项目。克隆进度放在模块级状态里，切到别的页面再回来还在；克隆中退出 SyncDeck 要确认（"退出会中断正在进行的同步或克隆"） |
| 超时和失败 | 克隆超时用设置里的「联网超时」。超时或失败后，如果目标文件夹是这次新建的（开始前不存在）就删掉，只删这一个；已存在的文件夹绝不动 |
| 私有仓库克隆失败 | 因为没有凭据（`Authentication failed`、`could not read Username`、`Repository not found`）失败时，原因后面加一句：先在命令行里用 git 登录一次 GitHub，SyncDeck 不会替你改 git 的全局配置 |
| 克隆之后 | 自动加入监控，并联网检查一次，结果直接显示在主页 |

【不做】

- 读取 Git Credential Manager 里的令牌，或在设置里填令牌
- 列出组织、协作的仓库（只列填写的这个账号名下的）
- 浅克隆、SSH 地址克隆（列表里一律用 https 的 `clone_url`）
- 克隆时弹 GitHub 登录窗口（沿用 `GIT_TERMINAL_PROMPT=0`、`GCM_INTERACTIVE=never`）
- 改全局 git 配置（包括 `gh auth setup-git`）
